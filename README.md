## 메뉴 추천

주문자 홈의 메뉴 추천 탭에서 지역을 선택하고 음식·인원·예산·취향을 입력합니다. 추천 API(`/api/recommend`)는 Supabase의 합성 가게·메뉴를 조회하고 DB 메뉴 가격과 배달비로 예상 총액을 계산합니다.

Gemini 키 없이도 규칙 기반 추천을 사용할 수 있습니다. 키가 설정된 환경에서 규칙 기반 모드로 시연하려면 서버 환경 변수 `RECOMMENDATION_MODE=rules`를 설정하세요. 메뉴 정보에서 확인한 조건을 카드에 표시하고, 치킨 후보에 순살과 뼈 있는 메뉴가 각각 있으면 선택지로 결과를 좁힐 수 있습니다. `안 매운` 요청에는 메뉴 정보에서 순한 맛을 확인할 수 있는 메뉴만 사용합니다.

Gemini를 사용하는 경우 Vercel 서버 환경 변수 `GEMINI_API_KEY`에 키를 저장합니다. 모델 기본값은 `gemini-3.5-flash-lite`이며 `GEMINI_MODEL`로 변경할 수 있습니다. 두 방식 모두 메뉴 카탈로그를 Supabase에서 조회합니다. `node --test`로 추천 로직을 검증할 수 있습니다.

## 사장님 메뉴 설명

사장님 라운지의 **메뉴 관리**에서 메뉴명과 가격을 입력하고 **AI 질문 시작**을 누릅니다. 양은 g 또는 인분으로 입력하고, 구성은 **+** 버튼으로 칸을 추가해 재료나 반찬을 하나씩 적습니다. 메뉴명과 구성에서 예상한 맛을 보고 해당 맛을 체크한 뒤 각각의 강도를 1~5단계에서 고릅니다. 매운맛을 체크하면 라면 기준과 SHU 추정도 볼 수 있습니다. [라면 비교값](https://github.com/park9896012-prog/K-Food-Guide-1/blob/main/src/data/kFoodData.ts#L370-L444)

고객에게 보여 줄 설명은 확정한 맛과 강도, 구성, 양을 문장으로 자세히 풀어 씁니다. 특징을 건너뛰면 유사 레시피에 어울리는 문구가 포함될 수 있습니다. 사장님은 출처를 확인하고 문구를 빼거나 설명을 수정한 뒤 저장합니다. **메뉴 정보와 설명 직접 수정**을 열어 바로 입력할 수도 있습니다. Gemini를 사용할 수 없으면 기본 질문, 맛 후보, 답변 기반 초안을 제공합니다.

배포할 때 [메뉴 추천 연동 마이그레이션](supabase/migrations/20261121120000_connect_merchant_menus_to_recommendations.sql)을 Supabase에 적용하세요. 기존 시연 방식에 따라 저장한 메뉴는 같은 브라우저의 주문자 화면과 추천에 반영됩니다. 저장된 맛·특징과 설명은 메뉴 매칭에 사용하고, 인분과 가격은 주문 구성과 총액 계산에 사용합니다.
