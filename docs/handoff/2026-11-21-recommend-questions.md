## 확인된 원인과 결정
- **맛 조건이 사라지던 원인**: `results()`의 `swapped`(비슷한 맛·조건 빼기) 경로가 이어서 고를 때도 돌고, 문구를 `state.excludeSeen ? '같은 조건에서…'`가 덮었다. → 이어서 고를 때(`excludeSeen`, `cheaper`)는 완화하지 않고 `tasteMissing`으로 사실+버튼. 첫 검색의 비슷한 맛 대체는 문구로 밝히고 버튼을 붙여 유지(팀 테스트 동작).
- **빼달라는 음식 오인 원인**: 빼기 표현이 "싫어/빼고/빼줘/제외"뿐이라 "안 돼/못 먹어/말고."가 음식 판정으로 넘어갔다. 조사 '이'를 떼서 "떡볶"으로 읽는 문제, "고기는"을 업종으로 먼저 읽는 문제도 있었다.
- **카테고리 오인 원인**: `MENU_WORDS`의 '해장'(→한식)·'야식'(→야식)이 상황 표현을 업종으로 만들었다. → 상황 단어는 `readContext`에서 먼저 떼어 소프트 가중치로만.
- **결정: 같은 동 0곳이면 3km 자동 확장**(새 지시서·팀 `search_rule`과 같음). 이전엔 버튼으로 고르게 했다(이전 지시서). 테스트 C·C2를 바꿨다.
- **결정: '안 매운'** — 치킨은 '안 매운' 표기 근거가 있어야 하고(팀 규칙, 팀 테스트), 다른 업종은 매운 근거가 없으면 충족. "매운 거 못 먹어"로 다른 업종이 0곳이 되지 않게.
- **결정: '느끼한 거' 빼기** — 크림·버터 등 근거 메뉴를 빼기만 하고 '담백' 맛 조건은 추가하지 않는다(정답 CSV가 담백을 넣지 않음).
- **결정: 브랜드·없는 메뉴** — 데이터의 가게·메뉴 이름에 실제로 있으면 대체하지 않는다.
- **사장님 메뉴 수정 반영**: 데모 카탈로그와 동 데이터의 id 체계가 달라, 수정 내역이 있는 브라우저만 Supabase 카탈로그 경로(`api/recommend.js`). 팀 결정 필요(이전 단계 문서).

## 주의할 점
- **데이터 값을 고치지 말 것**. 루트 원본 CSV가 기준이고 `dist/data`는 빌드 산출물(커밋하지 않음).
- **DB 마이그레이션은 팀 합의 없이 적용하지 말 것**. `main` 직접 push·force push 금지.
- 기존 테스트는 비대화형 엔진(합성 데이터) 기준, 서버는 `guided: true`. 평가 스크립트도 `guided: true`.
- 평가 숫자가 달라지면 먼저 `dist/data`가 빌드됐는지, Node 버전, 시드(`--seed`)를 확인한다.
- 성별 단어는 조건으로 쓰지 않는다(남자친구·여자친구는 인원 2명으로만).
- Windows 셸에서 한글 heredoc·python 인라인이 깨질 수 있다 → 스크립트를 파일로 써서 실행.
