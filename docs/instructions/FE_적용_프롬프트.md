너는 해커톤 배달앱 데모의 프론트엔드 개발을 돕는 역할이야.
이 앱은 기존 공공배달앱을 개선하는 데모야. 손님이 말로 조건을 말하면 AI가 동네 가게 메뉴를 골라주고, 착한가게 필터도 있어.
아래 데이터 파일과 규칙을 지금 프로젝트에 적용해줘. 먼저 지금 프로젝트 구조를 확인하고, 기존 코드 스타일에 맞춰 작업해줘.

## 1. 데이터 파일 (프로젝트 data/ 폴더에 넣을 것)
| 파일 | 내용 |
|---|---|
| hackathon_stores_excel.csv | 가게 62,000곳 |
| hackathon_menus_part1~4.csv | 메뉴 323,828개를 4개로 나눈 것(열 동일, 순서대로 이으면 전체). 한 가게의 메뉴는 한 파일에 모여 있음 |
| dong_centroids.csv | 서울 458개 동의 중심 위도·경도 |
| delivery_zone_3km.csv | 주문자 동 → 3km 안의 가게 동, 거리(km) |
| searchRule.js | 검색 규칙 함수 searchStores(), nearestDong() |

- 모든 CSV는 UTF-8(BOM 포함일 수 있음). 파싱할 때 첫 열 이름 앞의 BOM(﻿)을 제거할 것
- 빈 값은 빈 문자열. true/false는 소문자 문자열

### 가게 열 (hackathon_stores)
store_id, name, dong, category, is_franchise, delivery_tip, rating, review_count, is_open, exposure_count, is_good_price, delivery_available
- rating이 빈칸이면 신규 가게("신규" 배지, 별점 대신 표시)
- is_good_price=true면 착한가게(필터·배지)
- delivery_available은 모두 true
- category 16종: 한식, 카페·디저트, 치킨, 분식, 중식, 피자, 돈까스·일식, 양식, 고기·구이, 패스트푸드, 야식, 족발·보쌈, 도시락·죽, 아시안, 샐러드, 편의점 (업종 칩은 하드코딩하지 말고 데이터에서 뽑을 것)
- 동 이름은 법정동 기준. 다른 구에 같은 이름이 있으면 "신사동(은평구)"처럼 구가 붙어 있음

### 메뉴 열 (hackathon_menus)
menu_id, store_id, name, price, description, review_count (review_count=그 메뉴가 언급된 리뷰 수(가상). 리뷰 1건에 메뉴 1~3개가 언급될 수 있어 메뉴들의 합은 가게 review_count보다 클 수 있음. 각 메뉴 값은 가게 review_count 이하. description은 빈칸일 수 있음, 쉼표가 들어간 값은 큰따옴표로 감싸져 있음 → CSV 파서 사용, split(",") 금지)

### 동 파일
- dong_centroids.csv: dong, sigungu, lat, lon, 음식점 좌표 수, 중심점 기준
- delivery_zone_3km.csv: customer_dong, customer_gu, store_dong, store_gu, distance_km → { customer_dong: { store_dong: distance_km } } 형태로 바꿔서 사용

## 2. 성능 (중요)
- 메뉴가 약 30MB라 화면 첫 로딩에 전부 불러오지 말 것
- 방법(택1, 지금 구조에 맞는 쪽): (a) 빌드 시 JSON으로 바꾸고 동별로 나눠서 필요한 동만 fetch, (b) 서버/DB에 넣고 동 조건으로 조회
- 가게 목록은 주문자 동 + 3km 안의 동만 메모리에 올릴 것

## 3. 검색 규칙 (searchRule.js 그대로 사용)
1. 주문자 동 결정: 손님이 동을 고르거나, GPS 좌표가 있으면 nearestDong(lat, lon, centroids)
2. 1단계: 같은 동 가게만 검색 (영업 중, 업종, 메뉴 키워드, 예산=메뉴가격+배달팁, 프랜차이즈 제외 여부)
3. 결과가 0곳이거나 손님이 "더 보기"를 누르면 2단계: delivery_zone_3km 기준 3km 안의 동까지 확장, 거리순 정렬
4. 결과에는 step("같은 동" / "3km 확장")을 함께 보여줄 것
5. 서초1·2·3·4동은 중심점이 같아 서로 거리 0km → 화면에 거리 표시할 때 0km는 "같은 동네"로 표시
6. 노출 횟수(exposure_count)는 모두 0에서 시작. 추천에 노출되면 1씩 올려서 같은 가게만 반복 노출되지 않게(동점일 때 노출 적은 가게 우선)

## 5. 지켜야 할 것
- 상호·메뉴·별점은 모두 가상 데이터. 실제 가게 이름이나 실제 브랜드명을 화면에 추가하지 말 것
- 기존 배달앱(땡겨요 등)의 로고·브랜드 색·이름을 그대로 쓰지 말 것
- 데이터 파일 내용(가게·메뉴 값)을 임의로 고치지 말 것. 바꿀 게 있으면 먼저 알려줄 것
- 작업이 끝나면 바꾼 파일 목록과 시나리오 테스트 결과를 정리해서 보여줘
